What belongs
in AGENTS.md

The file an agent reads before code is a router, a set of hard rules, and a list of locks. It is not a diary, and it is not a second copy of every doc in the repo.

↓ The file that collapsed orientation
01
The first file

The first file
is not code.

In Built From the Rubble I wrote that a good AGENTS.md cuts orientation from about twenty minutes to about two. The measured version of that claim is more specific. Before the pivot, a session opened with fifteen to twenty minutes of “which service handles this?” After it, orientation was about two minutes: read AGENTS.md, open the controller, start the work.

That is the job of the file. It does not implement the order flow. It tells the agent which instruction source is authoritative, which docs exist by name, and which moves are forbidden. Qwen Coder, the operator named in that essay, reads AGENTS.md at the start of a session, runs tests before calling the work done, and logs what it changed.

Steller keeps two of these files, and they are not the same document. The root file is a workspace router. The backend file is the hard-rules list. Treating either one as a place to paste a design essay is how the file stops being readable in one sitting — the same failure mode the architecture essay describes for a controller that handles dozens of flows.

“The unit of architecture for agentic development is not the service boundary — it’s the context window.”
Built From the Rubble · March 2026

AGENTS.md is architecture for that window. If the first file the agent loads is long, vague, or full of secrets, the rest of the session inherits the waste.

02
Router and rules

A short router.
A longer lock file.

The root AGENTS.md is the Steller workspace agent router. It is 63 lines. Its instruction is to read it first in order to choose an instruction source. Backend tasks go to backend/AGENTS.md, which the root file names as authoritative. That backend file is 121 lines of hard rules. steller-backend/AGENTS.md is a symlink to ../backend/AGENTS.md, so there are not two backend policies.

The default reading of “Read AGENTS.md” is a policy-readiness check and a runtime-status check. It is not an invitation to redesign the platform before the checks have been done. Closed-loop CI is part of that reading: gh workflow run, gh workflow list, and gh workflow view.

The router also carries the release rule that shows up again in the backend file: never push directly to main. The path is a feature branch, then tests, then a pull request, then auto staging. Production is manual, and it requires human approval. A developer-hub repository is separate. When the hub and the backend conflict on backend behavior, the backend wins.

03
Scope map

Point at docs.
Do not paste them.

The root router maps scope to documents by name. The names it points at are: transferable knowledge, environments, one database per environment, the staging index, the backlog, the CI/CD guide, releases practices, the developer-hub deploy, and the Muhanad blog runbook. Those are pointers. This essay does not quote their bodies. Several of them were seen as names, not read as text, and inventing their contents would make AGENTS.md look more complete than the record is.

A scope map belongs in the router because an agent will otherwise guess which document is current. The rubble essay’s scorecard puts the failure mode plainly: when each service has its own docs, the agent cannot tell which are current. One AGENTS.md, one port map, one backlog is the published counter-move. The port map and the backlog are named there. Their contents are not restated here.

Precedence follows from the same map. Start at the root router. If the task is backend, the backend file wins over a general note. If the question is how the public API behaves for a partner, the developer hub at developers.steler.org is the published surface, and the backend file still wins on a conflict about backend behavior. The blog explains decisions. It is not the lock file.

What this essay will not do. It will not offer a blank template beyond the two files Steller actually keeps. A third AGENTS.md for a product that does not have this split would be an invention.
04
The locks

Non-negotiables
are remediation locks.

The backend file is where Steller’s real AGENTS.md practice gets specific. These are not preferences. They are written as locks: an agent that “improves” them is breaking the file. The rubble essay called the same idea confirmation gates and remediation locks — make the wrong move unambiguously wrong.

Lock
Backend AGENTS.md
CORS
Only explicit origins. Never a wildcard in production.
Hangfire workers
WorkerCount must be 2 for Bamboo. Never increase it.
PlaceBambooOrderJob
No retry. Refund on failure. Swallow a refund throw.
Bamboo calls
Always send an Idempotency-Key on vendor calls.
JWT_KEY
Never hardcode it in source. Always read it from the environment.
Catalog validation
Never coalesce nulls. Keep a strict schema.
Business claims
Never bypass RequireBusinessClaimsMiddleware.

Around those locks, the same file states operating rules that are just as easy to “helpfully” violate. Never push to main. Never delete, recreate, or rewrite model, migration, or context files. dotnet build stays at zero errors. Environment variables use a double underscore. Verify the business outcome, not only HTTP 200. After a config change, smoke the path: POST /api/orders returns 202, then poll until Completed. Fix tests only in test files. Pass the health gate before that smoke.

A lock belongs in AGENTS.md when breaking it looks like a local improvement. Raising Hangfire’s worker count looks like throughput. Retrying PlaceBambooOrderJob looks like reliability. Coalescing a null catalog field looks like tolerance. Hardcoding JWT_KEY looks like a faster local run. The file exists so those moves are named as forbidden before the agent reaches for them.

What does not belong in the lock list is a story about why the number is 2, or a pasted vendor contract, or a production secret. The rule is the rule. The motive, where it was not written down, stays unwritten.

05
Closed loop

Done means a run,
not a reassurance.

The eighth published agent-building rule in the rubble essay is to log what the agent changed, and the seventh is to require test output before “done.” The backend file makes the test side concrete: build at zero errors, change tests only inside test files, and smoke a real order through 202 to Completed after config changes. The root file makes the CI side concrete: run, list, and view the workflow with gh rather than declaring the branch finished.

That is closed-loop CI as a contents rule for AGENTS.md. The file should name the commands that prove readiness. It should name the branch policy. It should say that production is a human approval, not an agent’s last step. It should not contain a transcript of the last run. A transcript goes stale inside a session. A command stays true.

The same standard decides what to leave out. Do not paste production base URLs, webhook secrets, or API keys. JWT_KEY is named only as a value that comes from the environment. Do not duplicate the developer hub’s endpoint catalog inside the router; point at the hub and let the backend file govern conflicts. Do not store a handover narrative that you cannot keep current. The next essay is about three protocol files the rubble essay names, and that this record cannot quote.

A short contents list

  • Which file to read next, and which file wins.
  • The docs that exist, by name, without forged summaries.
  • The branch, test, and production-approval path.
  • Locks an agent will be tempted to relax.
  • The smoke that counts as a business outcome, not only a status code.

If a sentence does not help the next session choose, forbid, or verify, it belongs in an essay or a changelog. It does not belong in AGENTS.md.

06
Two minutes

Orientation collapsed
because the file was short.

The before-and-after in the rubble essay is the acceptance test for everything above. Fifteen to twenty minutes was the cost of a system whose first question was “which service handles this?” About two minutes is read AGENTS.md, open the controller. The golden flow — wallet debit, Bamboo, PIN, webhook — sits in one path the controller can show. The router’s job is to send the agent there without a tour of the repo.

I am not a developer. I build Steller with agents, from Mississauga, with no engineering team. The file works for that arrangement only if a new session can obey it without me re-explaining the locks. That is what belongs in AGENTS.md: the choice of source, the map of names, the commands that close the loop, and the rules that must not be improved.
